# 新手视角走查报告（2026-09-13）

用浏览器自动化以"从没用过的新手"视角实跑本系统（http://127.0.0.1:8899，全程截图 + SSE 抓取 +
`/api/status` 轮询 + task report 核对）。走查的场景是本会话讨论过的全部任务：生图（全身照）、
局部修复（脸部/手）、缺模型下载弹窗、设置/重扫等零散交互。

## 走查前的状态

- 服务在跑：Web UI 8899 / ComfyUI 0.33 (RTX 5070 Ti Laptop 12GB)，空闲 10.8GB，54°C，`stale_code: false`。
- **开局撞上的第一个坑：LLM 服务商 402 余额不足**（视觉自检直接显示 `LLM HTTP 402: 余额不足`，
  大脑文字调用同样会失败）。用户换上了火山引擎的新 Key（`glm-5-3-flash-260828`，一个模型同时
  覆盖大脑与视觉——实测它接受图像输入，`doubao-vision-*` 系列在该账户下未开通端点 404）。
  配置后在 ⚙ 面板里视觉自检变为「✅ 可用（已实测看图）」。

## 各场景体验记录

### S0 首次打开
- 顺畅：状态行/阶段条/画廊/工作流空提示都正常，顶部无异常告警。
- 困惑：落在"6"项目（localStorage 记忆），画廊里**全是旧的遮罩预览（黑底白块）和失败产物**，
  新手无法分辨哪些是"能用的结果"；默认项目还有 76 个历史文件。
- **发现①（中）**：局部修复的**遮罩预览（黑底白块）作为普通产物进了画廊**，对新手是噪音/惊吓；
  建议标记为调试产物或不进画廊。

### S1 新建项目
- 顺畅：点「＋新建项目」→ 输入名称 → 自动创建并切换；聊天/工作流清空，画廊出现
  "该项目暂无产物。历史资产在「默认项目」…"的引导（这句对新手很友好）。
- **发现②（高）切项目竞态**：切换后**画廊短暂显示上一个项目的产物**（`refreshGallery` 的异步
  竞态，随后才被新项目状态覆盖）——新手会以为那些图属于新项目。
- 测试性备注：`＋新建项目` 用的是浏览器原生 `prompt()`，人类没问题，但浏览器自动化无法驱动
  （走查里改用同一服务端点 `POST /api/projects` 代做）。

### S2 设置面板
- 顺畅：新 Key 保存即热生效；视觉行清楚显示「视觉地址：跟随大脑 · 视觉 Key：跟随大脑 ·
  自检：✅ 可用（已实测看图）」；402 期间则如实显示失败原因——这次的"余额不足"就是被它
  第一时间暴露的（而不是静默失败）。

### S3 文生图（"画一张白发紫瞳少女的全身照，厚涂动漫风格"）
- 顺畅：一次渲染出图；评估卡显示判据「必须全身：从头到脚完整可见（含脚/鞋）」——
  **"全身照"这个要求真的进了判据**（9/10 通过）；产物自动入画廊。
- **发现③（高）交付文案**：正文以「（轮数用尽，先汇报当前结果）」开头——内容其实齐全
  （产物/位置/评估 9/10/对照要求），但"轮数用尽"对新手是黑话，像出了故障；
  实际只是一轮就完成并被兜底文案接管。建议改为"已完成，先给你看当前结果"之类的自然表述。
- 小记：大脑发明了 `hires=True` 参数（不合法，已回落）——护栏接住了，但说明仍在猜参数。

### S4 上传图 + 局部修复（"脸部和手有一些失真，帮我修一下"）
- 顺畅：**两次链式局部修复（hand→face）全部成功**，2 次渲染 0 浪费；
  - `denoise=0.5` 被护栏自动收敛为 0.85（低于 0.85 会留灰块——实测教训进了护栏）；
  - 两次遮罩都是**真局部**（hand 1.18%、face 1.81%，bbox 集中在手/脸）；
  - 第二次以第一次的产物为基底（引擎自动找到并上传），**区域外 0 像素改动**（逐像素校验）；
  - 交付引用契约判据：「对照你的要求：面部五官正常…；手部结构正常…」+ 评估 8/10。
- 困惑：大脑先调 `analyze_image{}`（本轮没传图、也没指路径）报"图片不存在（未提供）"——
  报错清晰但新手会懵；建议此时回退为"分析最近一次产物"。
- 小记：交付正文仍是发现③的兜底文案开头。

### S5 缺模型下载弹窗（"帮我下载一个头发分割模型 hair_yolov8n-seg_60.pt"）
- 顺畅：大脑自己 `search_models`（命中本机 Manager 目录，5 个 face/hair 候选）→ `download_model`
  → 弹窗信息完整：文件/名称/大小 6.46MB/来源/适配/**加载节点 AILab_YoloV8Adv**/存放目录；
  点「下载」后同窗进度条（百分比/速度/已用时长/取消），完成后校验 ok（6,770,680 字节落盘）；
  世界清单自动刷新（`ultralytics: 4→5`），不需要手动重扫。
- 对话里的系统消息是**中性**的：「模型已就绪…它属于哪个链路…本轮并没有因缺模型失败的任务在等它」
  ——没有编造"刚才失败的任务"（这是之前修过的点，实测保持）。
- **发现④（中）弹窗完成文案不一致**：下载完成后弹窗仍显示「✅ 下载完成，正在自动重跑刚才
  失败的任务…」，但这次根本没有失败任务（聊天里的系统消息是中性的）——弹窗文案应与
  系统消息一致。
- 小记：GitHub release 经代理只有 ~30KB/s（6.46MB 下了一分多钟）——速度是网络问题不是代码问题，
  但弹窗全程有进度可见，体验 OK。

### S6 零散交互
- ⟳ 重扫：状态行显示「已重扫 · 节点 1527 · ultralytics: 5」——新下载的模型立刻可见 ✓。
- 画廊灯箱：点开/关闭正常 ✓；项目切换往返正常 ✓。
- **发现⑤（低）顶栏拥挤**：加了 ⟳ 之后 1280px 宽度下「ComfyUI 大脑」标题和「＋新建项目」
  换行，略显凌乱。
- **发现⑥（低）**：`webui.log` 里大量 `WinError 10053` 连接中止堆栈（SSE 断开的正常噪音），
  翻日志会吓一跳；建议降噪或注释说明。

## 汇总：按严重度排序的 UX 问题

| # | 严重度 | 问题 | 建议 |
|---|---|---|---|
| ① | 中 | 遮罩预览（黑底白块）混进画廊产物 | 标记为调试产物，不进画廊或加"遮罩"角标 |
| ② | 高 | 切项目时画廊显示上一项目产物的竞态 | `refreshGallery` 带项目参数/取消旧请求 |
| ③ | 高 | 交付正文以「（轮数用尽，先汇报当前结果）」开头 | 兜底文案改自然表述（"已完成，这是当前结果"） |
| ④ | 中 | 下载完成弹窗文案与实际不符（无任务却提"自动重跑"） | 弹窗文案按有无重跑前提区分 |
| ⑤ | 中 | 服务商 402/401 这类错误的呈现太技术化 | 专门文案："账户余额不足/Key 无效 → 去 ⚙ 检查" |
| ⑥ | 低 | 本轮无上传图时 `analyze_image{}` 报"图片不存在（未提供）" | 回退为分析最近一次产物，或提示更明确 |
| ⑦ | 低 | `＋新建项目` 用原生 prompt()（风格不统一、自动化不可测） | 换成应用内小输入框 |
| ⑧ | 低 | 顶栏 1280px 下换行拥挤 | 图标化/收纳次要按钮 |
| ⑨ | 低 | webui.log 的 SSE 断开堆栈噪音 | 降噪或注释 |

## 走查证明的机制（都是真机验证，非文档自述）
- 判据进评估：「全身照」「面部/手部失真」都成了评估标准（9/10 与 8/10 两次都是对着用户要求判的）；
- denoise 护栏：大脑传 0.5 被收敛为 0.85（灰块教训进了引擎）；
- 下载弹窗的"加载节点"行、中性系统消息、世界清单自动刷新；
- 局部修复的区域外 0 像素改动（hand 1.18% / face 1.81% / 链式第二次也成立）；
- view_image 复用引擎评估（不重复烧 VLM）。
