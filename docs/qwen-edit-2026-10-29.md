# Qwen-Image 2.1 指令改图（qwen_edit）接线记录 · 2026-10-29

## 为什么做

本机（RTX 5070 Ti Laptop，12GB）`checkpoints/` 是空的，只有一套 Qwen-Image 2.1 量化栈：
`diffusion_models/qwen_image_2.1_int8_convrot` + `text_encoders/qwen3vl_8b_int8_convrot` +
`vae/qwen_image_2.1_vae_bf16`。也就是说 SDXL 系模板（i2i / style_transfer / inpaint…）在这台
机器上根本跑不起来，而 Qwen 的"看图 + 按指令改图"能力恰好补上了这个缺口——它不是"重画一张
相似的图"，参考图是真的进了模型。

## 接线

```
UNETLoader(qwen_image_2.1_int8_convrot, default) → ModelSamplingAuraFlow(shift=3, flow)
CLIPLoader(qwen3vl_8b_int8_convrot, type=qwen_image) ┐
VAELoader(qwen_image_2.1_vae_bf16)                   ├→ TextEncodeQwenImage21(clip, prompt,
LoadImage(用户图)                                     ┘   negative, images, resolution, vae)
     └→ positive["6",0] / negative["6",1] / latent["6",2]
KSampler(denoise=1.0) → VAEDecode → SaveImage(agent_qwen_edit)
```

`TextEncodeQwenImage21` 一次吐三路，这是它和普通 CLIPTextEncode 最大的不同：
`(positive, negative, latent)`。latent 的尺寸取**第一张参考图**（`[1,64,h//16,w//16]`），
所以 `resolution` 参数只影响视觉 token 的短边缩放，真正出图尺寸跟参考图走。

实测的语义差异（comfy_extras/nodes_qwen.py）：

- **给 vae**：`keep_vision=False`，参考图走 VAE 潜变量，路径短、快；
- **不给 vae**：参考图走视觉塔 token，也更"理解"语义，但慢一些。

两者在 768² 探针图上出图肉眼无差别（PNG 字节 659093 vs 659082）。v1 默认走带 vae 的分支。

## 实测数据（真机，ComfyUI v0.38.0-21）

| 接法 | 耗时 | 结果 |
|---|---|---|
| edit（带 vae） | 冷启 51.2s / 热 30.2s | ✅ 红圆变蓝，构图保持 |
| edit_novae（不带 vae） | 30.1s | ✅ 与上面肉眼无差别 |
| ControlNet：fun controlnet union，控制图 = **RGB 原图**，strength 0.85 | 48.2s | ❌ 花屏：矩形被抹成灰块、出现乱码纹理 |
| ControlNet：控制图 = **Canny 边缘图**，strength 0.7，start 0 / end 1.0 | 45.1s（直连）/ 39.3s（经引擎） | ✅ 红圆 → 金属蓝圆盘，边缘与原图重合 |
| ControlNet：Canny，strength 1.0 + end_percent 0.5 | 30.2s | ❌ 出图右下角多出乱码文字（后期放开模型后自创内容） |

**ControlNet 的结论**：花屏不是补丁坏了，而是**控制图喂错了**。fun controlnet union 要的是
结构图（边缘/深度/姿态这类），直接把 RGB 照片当控制图 → 花屏。换成 Core 的 `Canny` 先提边缘、
strength 保留 0.7、且**不要把 end_percent 提前**（提前放开会让模型在剩余步数里自创文字），
结构就能稳稳锁住。`structure="canny"` 走的正是这条链。

## 局部改图（region）：裁剪 → 重绘 → 原位贴回

`region="x,y,w,h"`（原图像素，左上角 + 宽高）时，链路变成：

```
LoadImage ─┬─→ ImageCrop(x,y,w,h) → TextEncodeQwenImage21.images   （只把这块喂给模型）
           └─────────────────────────────────────→ ImageCompositeMasked.destination
VAEDecode → ImageScale(回到 w×h, lanczos) → ImageCompositeMasked(source) → SaveImage
```

两个坑（都有源码依据，`comfy_extras/nodes_mask.py:12`）：

1. `ImageCompositeMasked` 的 `resize_source` **必须 False**。置 True 时它把 source 插值到
   **整张 destination 的尺寸**（`interpolate(size=destination.shape[-2:])`），贴回去就是
   全图错位；正确做法是自己先用 `ImageScale` 压到 `w×h` 再贴。
2. 重绘结果是**正方形**（边长由 `resolution` 决定），非正方形区域靠 `ImageScale` 的
   `crop="center"` 压回去，会有轻微纵向/横向压缩——换来的是区域外像素绝对不动。

实测（768×768 探针图，region=20,600,240,240，即左下角矩形所在块）：

- 产物 768×768（原图尺寸不变），13.4s（512 潜空间，比整图快一倍多）；
- **区域外像素逐位相同**：与原因做差后，区域外最大通道差 = 0、变化像素数 = 0、包围盒 = None；
- 区域内是整块重绘，不是"只改那个矩形"——想精确到物体请把 region 框小。

## 一指令多图（batch）

`batch=1..4` 在编码器和 KSampler 之间插 `RepeatLatentBatch`（`samples` 接编码器 latent 输出），
同一提示词一次采样出 N 张。实测 batch=2：47.7s、两张 1024²、tier0 全 pass。
局部改图模式固定 1 张（贴回逻辑按单张设计，多张会互相覆盖）。

## 使用边界（写进提示词里）

- 1024 级重绘**不是像素编辑**。第一次只让它「把圆的颜色改成蓝色」，左下角的小矩形整个消失了。
  所以系统提示里要求：指令必须显式说明"其余保持不变"，模型才会保住没被提到的元素。
- 提示词要用**自然语言指令句**，不要堆 `masterpiece, best quality` 标签（那是 SDXL 的习惯）。
  `promptspec` 的 qwen 家族指南会拦这类写法。
- 改图属于图像家族：不该出现"缺镜头词、视频会变静帧"这类视频警告——`_VIDEO_FAMILIES`
  只覆盖 minimax / ltx，qwen 在 `_NL_FAMILIES` 里但不做动作/镜头检查。
